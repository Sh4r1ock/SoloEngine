## 一、项目管理API修改

### 1.1 问题分析

**当前代码问题：**
- `run_project.py` 中的 `/select-folder` 和 `/native-folder-dialog` 接口没有接收 `agentic_flow_id` 参数

- `run_project_id` 是根据 `path + user_id + agentic_flow_id` 获取的

### 3.4 关于 addSession 接口的详细说明

**当前代码问题：**
```typescript
// runStore.ts 第130-148行
addSession: (session: Partial<ExtendedRunSession>) => {
  const newSession: ExtendedRunSession = {
    id: session.id || `session-${Date.now()}`,
    status: session.status || 'running',
    // ...
  };
  set((state) => ({
    sessions: [...state.sessions, newSession],
    activeSessionId: newSession.id,
    currentSession: newSession,
  }));
},
```

**问题分析：**
1. `addSession` 在前端 store 中创建 session 对象
2. 这只是前端内存中的操作，并没有持久化到数据库
3. 这种设计是不必要的，前端只需要存储 `currentSessionId`

**正确做法：**
1. 前端创建新对话时，生成 `session_id`（UUID）
2. 前端直接使用这个 `session_id`，设置到 `currentSessionId`
3. 前端不持久化到数据库，只存储 `currentSessionId` 在内存中
4. 对话时，`session_id` 跟 `agentic_flow_id`、`user_id`、`run_project_id` 一起传到 SoloAgent 层
5. SoloAgent 层读取记忆，如果记忆为空则创建 session 记录
6. **执行完成后，前端调用 `loadSessionsFromBackend()` 刷新任务栏，获取完整数据**

## 四、工作流执行修改

### 4.1 问题分析

**当前代码问题：**
- 前端在 `handleSendLLMMessage` 中调用 `addSession`，向前端 store 添加 session
- 前端没有正确处理 session 的创建流程

**正确流程（参考 session-message-design-spec.md）：**

```
┌─────────────────────────────────────────────────────────────────┐
│                        正确的流程                                │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  1. 前端创建新对话                                               │
│     └── 直接在前端代码中创建 session_id（UUID）                  │
│     └── 设置 currentSessionId                                   │
│     └── 创建临时任务（仅用于显示，数据不完整）                    │
│     └── 不调用任何API                                            │
│     └── 不持久化到数据库                                         │
│                                                                 │
│  2. 前端发送消息                                                 │
│     └── 将 session_id、agentic_flow_id、user_id、run_project_id │
│         和消息内容一起传递给后端                                   │
│     └── 不使用任何其他API                                        │
│                                                                 │
│  3. 后端 SoloAgent 层处理                                        │
│     └── DatabaseMemoryPlugin 初始化获取记忆                      │
│         └── 加载历史消息（如果是新 session 则会直接返回空列表）    │
│         └── 如果记忆为空 → 创建 session 记录                      │
│     └── 执行推理                                                 │
│     └── DatabaseMemoryPlugin.add() 保存消息                      │
│                                                                 │
│  4. 执行完成后                                                   │
│     └── 前端收到 execution_complete 事件                         │
│     └── 调用 loadSessionsFromBackend() 刷新任务栏                │
│     └── 获取完整的、更新后的会话列表                              │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

```typescript
const handleSendLLMMessage = async () => {
  if (!llmInput.trim()) return;
  
  let currentSessionId = activeSessionId;  // 使用 currentSessionId
  
  // 前端创建新任务时，生成UUID（不调用API，不持久化）
```

```typescript
const loadSessionsFromBackend = async () => {
  if (!flowId) {
    console.log('No flowId, skipping session load');
    return;
  }
  
  if (!currentProject?.id) {
    console.log('No currentProject, skipping session load');
    return;
  }
  
  try {
    // 通过 agentic_flow_id、run_project_id 获取
    // 前端发送这些参数，后端来查询
    const sessions = await runApi.getSessions({
      agentic_flow_id: flowId,
      run_project_id: currentProject.id,
      limit: 50
    });
    
    // 仅用于显示，不持久化
    const loadedTasks: Task[] = sessions.map(session => ({
      id: session.id,
      name: `会话 ${session.id.substring(0, 8)}`,
      createdAt: session.created_at || new Date().toISOString(),
      messages: [],  // 消息按需加载
    }));
    
    setTasks(loadedTasks);
  } catch (error) {
    console.warn('Failed to load sessions:', error);
  }
};
```

### 4.5 Memory 处理流程

**重要说明：**

前端获取对话历史仅用于显示。Memory 是在 SoloAgent 中读取并传入到 ReActCore 中的。

**具体流程：**
1. 前端发送 `session_id`、`agentic_flow_id`、`user_id`、`run_project_id` 到后端
2. 在 SoloAgent 层：
   - DatabaseMemoryPlugin 初始化获取记忆（使用session_id、user_id）
   - 加载历史消息（如果是新 session 则返回空列表）
   - 如果记忆为空 → 创建 session 记录（使用agentic_flow_id、前端给定的session_id、user_id、run_project_id创建）
3. SoloAgent 将上下文传入到 ReActCore 中
4. ReActCore 本身的职责，只有：执行、接收数据

### 5.1 统一命名规范

根据 `session-message-design-spec.md`，统一以下变量名：

| 旧名称 | 新名称 | 说明 |

### 5.2 会话统一命名为 Session

所有会话相关的变量、函数、接口统一使用 Session 命名：
- `sessions` - 会话列表
- `currentSessionId` - 当前会话ID
- `currentSession` - 当前会话对象
- `loadSessions` - 加载会话列表
- `loadSessionMessages` - 加载会话消息

之前似乎有task_id，如果其代表会话，需要改为session_id
同理，以本文档为准。如果 有同作用 近义词 需要修改为本文档中的标准名称。

## 八、注意事项

1. **前端不持久化到数据库**：前端只存储 `current_session_id`、`current_run_project_id`、`agentic_flow_id`、`user_id` 等传输所需的 ID 在内存中，不进行数据库持久化。

2. **session_id 由前端生成**：前端创建 `session_id`（UUID），直接使用，不需要等后端返回。

3. **session 记录由后端创建**：在 SoloAgent 层，DatabaseMemoryPlugin 初始化时，如果记忆为空则创建 session 记录。

4. **执行完成后刷新任务栏**：前端收到 `execution_complete` 事件后，调用 `loadSessionsFromBackend()` 刷新任务栏，获取完整的、更新后的会话列表。

5. **Memory 在 SoloAgent 层**：对话历史的 memory 是在 SoloAgent 中读取并传入到 ReActCore 中的，前端获取对话历史仅用于显示。也是在SoloAgent层保存到数据库中的。

6. **ReActCore 职责**：ReActCore 本身的职责只有执行和接收数据，不负责持久化。

7. **编译与运行分离**：
   - 编译过程：只需要 agenticflow.json，不要其他参数
   - 运行过程：需要 run_project_id、user_id、session_id 等参数

8. **run_project_id 获取**：`run_project_id` 是根据 `path + user_id + agentic_flow_id` 获取的。选择 run_project 后，前端需要一直存着这个 id，直到下次进行修改。
