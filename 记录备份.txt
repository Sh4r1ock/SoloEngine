# **Agentic AI可视化低代码平台——技术实施方案**

## **一、项目概述与目标**

### **1.1 项目背景与愿景**

本项目致力于构建一个革命性的低代码/无代码平台，核心目标是**将复杂的Agentic AI（自主多智能体协作系统）的开发门槛降至最低**。与仅编排确定性流程的Workflow工具（如Dify）不同，本平台聚焦于构建具备自主规划、动态决策与协作能力的多智能体系统。用户通过简单的拖拽、连线与配置，即可像组装乐高一样，创建出能理解高层目标、智能拆解任务、并自主执行的“AI团队”。

### **1.2 核心设计理念**

1.  **三层抽象**：通过 **Orchestrator（协调者）**、**Planner（规划者）**、**Executor（执行者）** 三种节点类型，封装多智能体协作的全部复杂性。

2.  **可视化优先**：所有智能体角色定义、协作关系、技能绑定均在前端画布中通过拖拽连线完成，生成可执行的“协作图”。

3.  **协议化通信**：前后端采用类似 **AG-UI** 的开放协议进行标准化通信，实现前端UI与后端AI智能体之间的实时、状态化交互。

4.  **生态集成**：原生适配 **MCP（Model Context Protocol）**、OpenAI Function Calling等标准，无缝集成外部工具与能力。

### **1.3 项目目标**

| 目标类型 | 具体描述 |

| :--- | :--- |

| **产品目标** | 上线一个功能完整的Web平台，用户可在画布上通过拖拽三种节点，配置提示词与技能，构建并运行一个多智能体应用。 |

| **技术目标** | 1. 实现一个可解析、执行“协作图”的高性能后端引擎。<br>2. 实现一个流畅、可实时预览的前端可视化编排器。<br>3. 建立标准化的前后端数据通信与状态同步机制。 |

| **体验目标** | 用户从零开始构建一个能完成多步骤任务（如“撰写市场分析报告”）的多智能体应用，整个过程不超过15分钟。 |

### **2.2 前后端分离与接口规范**

*   **通信方式**：常规配置操作使用 **RESTful API**，任务流式执行与状态同步采用 **WebSocket** 或 **Server-Sent Events (SSE)**，遵循类似AG-UI的标准化事件类型。

*   **接口设计原则**：严格遵循**RESTful**风格，进行清晰的**版本控制（如/v1/）**，请求与响应体统一使用**JSON格式**，并包含标准化的状态码、消息及数据体。

*   **安全与认证**：采用**JWT（JSON Web Tokens）** 进行用户身份验证与API权限控制。

## **三、核心模块详细设计与实现**

### **3.1 前端模块：可视化编排器**

1.  **技术栈**：React 18 + TypeScript + React Flow（流程图库） + Ant Design / MUI。

2.  **核心组件**：

*   **画布(Canvas)**：基于React Flow，支持三种节点的拖拽、连线、删除。连线即代表智能体间的“协作关系”或“汇报路径”。

*   **节点属性面板**：

*   每个节点具备**系统提示词（System Prompt）**、**用户提示词（User Prompt）**、**助手提示词（Assistant Prompt）** 的编辑框（支持变量插值，如`{available_agents}`）。

*   **技能绑定区**：以多选或标签形式，将平台集成的MCP工具或自定义技能绑定到该节点。

*   **模型配置**：选择该节点使用的LLM及参数。

*   **连线智能配置**：

*   当从`Orchestrator`连线至`Planner`时，前端自动在`Orchestrator`的提示词模板中插入片段：“规划师`{Planner.name}`（简介：`{Planner.desc}`）可用于拆解复杂目标。”

*   当`Planner`连线至多个`Executor`时，这些`Executor`的ID和简介将自动汇总为`{available_executors}`列表，插入`Planner`的提示词中。

3.  **数据持久化**：画布的所有状态（节点、连线、配置）实时序列化为一个**JSON Schema**，保存至后端数据库。此Schema是后端引擎执行的唯一蓝图。

### **3.2 后端模块：Agentic 运行时引擎**

1.  **技术栈**：Python 3.10+（FastAPI/或基于FastAgency的框架）， 使用异步编程以提高并发性能。

2.  **核心服务**：

*   **画布解析器**：接收前端传来的画布JSON，验证其有效性，并实例化为一个包含节点对象和边关系的“协作图”数据结构。

*   **节点基类与工厂**：

```python

class AgentNode:

id: str

name: str

node_type: Literal["orchestrator", "planner", "executor"]

config: dict # 包含提示词、模型设置等

def run(self, global_context: dict) -> dict: # 返回执行结果和下一步指令

pass

class OrchestratorNode(AgentNode):

# 负责管理整体流程，调用Planner，按计划调度Executor

pass

class PlannerNode(AgentNode):

# 接收目标，输出结构化步骤计划（JSON格式）

pass

class ExecutorNode(AgentNode):

# 接收具体步骤，调用绑定技能完成任务

pass

```

*   **上下文管理器**：维护一个全局字典`GlobalContext`，贯穿任务始终，包含`user_input`、`current_plan`、`execution_history`等，作为节点间共享数据的唯一通道。

*   **工具集成层**：

*   实现一个`ToolRegistry`，统一注册和管理所有可用技能。

*   对MCP工具，使用官方SDK创建客户端并动态加载工具列表。

*   对所有技能暴露统一的`call_tool(tool_name: str, arguments: dict)`方法。

*   **执行调度器**：作为一个状态机，从“协作图”的入口节点（通常是Orchestrator）开始，调用其`run()`方法，并根据方法返回的`next_node_id`，驱动下一个节点运行，直至流程结束。

### **3.3 前后端对接：状态同步与协议**

*   **采用AG-UI协议适配**：后端引擎将`Orchestrator`、`Planner`、`Executor`节点的执行过程，映射为AG-UI协议定义的标准化事件（如`agent-update`、`tool-call`、`response-streaming`）。

*   **前端运行时监控**：前端通过WebSocket连接，订阅这些事件，实时将智能体的“思考”、“规划”、“工具调用”、“结果产出”以日志或可视化流程的形式展示给用户，实现强大的**可观测性**。
